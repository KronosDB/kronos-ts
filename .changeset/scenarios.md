"@kronos-ts/test": minor

Tests are written in the shapes an event model is written in. `scenario(subject)` and `storyline(...)` replace `testFixture`, and assertions are plain functions of the outcome.

- `scenario(subject).given(...events).when(act).then(...assertions)` runs the scenario and resolves with its `Outcome`. `subject` is a slice's three lists as the slice writes them, or a scope `(resources) => lists`. There is no fixture to build and no `run`. Each scenario gets a world of its own; `.and` continues the same world for the next step (`.then(...).and.when(...).then(...)`), which replaces consecutive `run` calls on one fixture.
- `given` events now reach projections. They are handed to every processor as a replay (`ctx.isReplay()` is true), and nothing an event handler sets in motion while they are folded gets out: a command it dispatches is not dispatched (`send` resolves to `undefined`), and a deadline it arms is not armed. Before, given events skipped every processor, so a read model could only be tested through events arriving.
- `storyline(subject, query(Q, payload)).shows(expected).after(...events).shows(expected)` walks one read model through its states, each judged once the events before it are handled.
- An assertion is `(outcome) => void | Promise<void>`: it returns when the claim holds and throws when it does not. `Outcome` has `act`, `result`, `threw`, `error`, `events`, `commands`, `schedules` and `app` (the resources, plus whatever the infrastructure brought). The built-ins are such functions: `events(...)`, `noEvents()`, `commands(...)`, `noCommands()`, `result(value)`, `error(matcher)`, `scheduled(...)` and `cancelled(...)`. `then(event(A), command(C))` becomes `then(events(event(A)), commands(command(C)))`. A function claims a throw by carrying `claimsError: true`, as `error()` does.
- `configure({ infrastructure, clock, within })` sets the defaults once for a test run, typically from a preload; a scenario's own options override them. The infrastructure factory may be async and is called once per scenario. Every member of what it returns is optional, and it can bring `wrap(handler, kind)` to wrap every handler, `close()` to release what it opened, and any other value, which reaches assertions on `outcome.app`.
- `then` reports every failing claim, not only the first. `.await(...)` is gone: on a foreign site (a brought log, or a processor over a store of its own) `then` re-judges until `within`, as `await` did.
- Removed: `testFixture`, `TestFixture`, `RunOutcome`, the free-standing `given(...)` and `scenario()` without a subject, the `Scenario` value, `Judgement`, `FixtureOptions`, `FixtureLists` (now `Subject`), `FixtureResources` (now `SiteResources`), `FixtureScope` (now `Scope`), `FixtureInfrastructure` (now `Infrastructure`), `FixtureEventHandler`, `FixtureUnitOfWork`, `EventRecording` and `IfAdvanceable`. `.advance(...)` is no longer refused at compile time on a scenario that cannot move time; it is refused when the scenario runs.
